# Cross-Repo Library & Operation Catalog

> **Purpose.** One reference for every library across the three sibling repos — `agg`,
> `001Cytometry`, and `granular-bunny` — with, for each: **what it does**, **its language**, and a
> **per-operation / per-file-format breakdown**, plus a **recommendation of *where* each operation
> should run** (pure TypeScript, WASM, `bun:ffi` native, or WebGPU) so the three can be orchestrated
> as one system.
>
> Scope note: this is a *decision* document, not an API doc. Where a repo already maintains an
> exhaustive per-function index, this file cites it rather than duplicating thousands of signatures
> (chiefly `agg/ports/PORTING_PROGRESS.md`, auto-generated by `gen_porting_progress.py`, and the
> `granular-bunny/src/gen/*.manifest.ts` binding manifests).
>
> Compiled 2026-07-09.

## 0. Orientation — the three repos and the four execution substrates

| Repo | Domain | What it *is* | Primary language(s) |
|---|---|---|---|
| **`agg`** | Bioinformatics (DNA cloning, sequence design, Sanger traces) | Python/R libraries **ported to idiomatic TypeScript**, merged into one headless "feature pool" (`agg/ports/<feature>/`) that powers an in-browser GenBank/cloning editor | TS (ports) ← Python/R (sources) |
| **`001Cytometry`** | Flow / mass / spectral cytometry | A cytometry analysis **engine + renderer**: FCS I/O, transforms, gating, clustering, dim-reduction, density plots. Mostly TS, with a **started Rust→WASM kernel crate** and a **WebGPU** renderer | TS + Rust (WASM) + WGSL |
| **`granular-bunny`** | Native-code acceleration harness | The **pattern factory**: vendors best-in-class C/Rust libraries as git submodules, compiles each to **both** a native shared lib (`bun:ffi`) **and** WASM, generates FFI bindings, self-tests all backends agree, and benches `FFI vs WASM vs TS` | C + Rust + TS (Bun) |

### The four places code can run

1. **TypeScript** — main thread or a Web Worker. Zero boundary cost, universal, GC'd. Best for
   orchestration, per-call-cheap logic, anything called in tight JS loops, and correctness-reference
   implementations.
2. **WASM** (`.wasm`) — runs in the browser **and** in Bun. Near-native compute, but data must be
   staged into linear memory and it is subject to the **wasm32 4 GB address ceiling**. Best for
   hot numeric kernels on bounded working sets.
3. **`bun:ffi` native** (`.dll/.so/.dylib`) — server/CLI only (Bun). Full-speed, real SIMD/AVX2,
   malloc/mmap/filesystem, **zero-copy on a `SharedArrayBuffer`**. Best for the heaviest server-side
   passes and libraries that need the OS (mmap, threads, WAL).
4. **WebGPU** (WGSL compute/render) — browser (and native via Dawn). Massively parallel. Best for
   per-pixel / per-event rendering and embarrassingly-parallel binning at interactive frame rates.

### The decision heuristic (used throughout this doc)

```
boundary-crossing cost (~10–100 ns/call)  vs  work done per crossing
├─ per-call cheap, called in a JS loop ............ stay in TS
├─ one crossing, heavy numeric loop, bounded data . WASM (browser) / FFI (server)
├─ needs OS (mmap/threads/FS/AVX2), server-side ... bun:ffi native only
├─ per-event / per-pixel at 60 fps ................ WebGPU
└─ deterministic + reused across backends ......... keep a TS reference as the self-test oracle
```

Two hard architectural constraints observed across the repos:

- **wasm32 4 GB ceiling.** `001Cytometry/packages/cytometry-core/src/matrix.ts` deliberately keeps
  the event matrix on the **JS heap in a `SharedArrayBuffer`**, *not* in WASM linear memory, because
  30M events × 50 channels ≈ 6 GB overflows wasm32 (Memory64 still absent from Safari as of 2026).
  Consequence: the **FFI path can be zero-copy** on those bytes; the **WASM path must stage** (fine
  for *reduced* working sets — you don't UMAP 30M events, you UMAP ≤500k after gating/downsample).
- **Determinism for self-tests.** `granular-bunny`'s harness refuses to time anything until every
  backend produces the *identical* known answer (`src/suite.ts` `selfTest`). Seed-dependent or
  float-reduction-reordered algorithms (UMAP, k-means, SIMD sums) need a *tolerance* oracle, not
  strict equality.

## 1. `granular-bunny` — the native library shelf

The scaffold (`scripts/build.ts`, `gen-bindings.ts`, `update-external.ts`, `src/suite.ts`) turns any
vendored C/Rust lib into three comparable backends. Adding a library = submodule it into
`external-libraries/`, teach `build.ts` to compile it, list it in `src/libs/registry.ts`.

## 2. `001Cytometry` — the cytometry engine

Monorepo of five packages. `cytometry-core` is pure-TS and enormous (600+ passing tests); it is the
**source of truth**, and the WASM/GPU paths must reproduce its outputs bit-for-bit (headless-first,
per `docs/DERISKING.md`).

### 2.0 Packages at a glance

| Package | Lang | Role |
|---|---|---|
| `fcs` | TS | FCS file parse/write, `$SPILLOVER` extraction |
| `cytometry-core` | TS | All the math: transforms, gating, density, compensation, clustering, dim-reduction, graph, stats, QC |
| `cytometry-gpu` | TS + WGSL | WebGPU density renderer, colormaps, axes, pan/zoom/gate interaction; Canvas2D fallback |
| `cytometry-wasm` | **Rust** | **Started** native kernel crate (logicle, gate, compensate, cluster) — the acceleration seam |
| `engine-controller` | TS | Orchestrator: worker RPC, undo/redo, workspace serialization, GatingML import, operation dispatch |

### 2.1 `fcs` — file I/O

Language TS. Files: `parse.ts`, `write.ts`, `header.ts`, `text.ts`, `data.ts`, `spillover.ts`.

| Operation | What / file-format details | Where |
|---|---|---|
| `parseFcs` | FCS **3.0 / 3.1**, `$MODE L` (list mode). Datatypes: `I` (integer, `$PnB` bits, `$PnR` range bit-masking — the FlowIO high-junk-bit fix), `F` (float32), `D` (float64), `A` (ASCII — delimited *and* fixed-width fallback). Endianness via `$BYTEORD`. HEADER↔TEXT offset reconciliation (large-file `$BEGINDATA`/`$ENDDATA` rule). Transposes row-major on-disk → **column-major** store. Pluggable allocator (`ParseOptions.alloc`) writes straight into a `SharedArrayBuffer`. | **TS today.** The tight decode+transpose inner loop (`data.ts:123`) is the one native candidate — a small C/Rust kernel over a staged buffer; parser control flow stays TS. |
| `writeFcs` | Serialize back to FCS 3.1; round-trips channels/labels/counts/spillover | TS |
| `parseHeader` / `parseText` | HEADER segment offsets; `$KEY/VALUE` TEXT dictionary w/ delimiter handling | TS (cheap) |
| `parseSpillover` | `$SPILLOVER`/`$SPILL` → channels + row-major compensation matrix | TS (cheap) |

### 2.2 `cytometry-core` — the math (per-module, with placement)

Each entry: capability → key exported ops → **where it should run**. Hot files already earmarked in
`src/kernels/types.ts` are flagged ⚡.

**Transforms** (`src/transforms/`) — per-column, transcendental-heavy, deterministic (golden-tested
vs flowutils oracle).
- `LogicleTransform` ⚡, `HyperlogTransform`, `AsinhTransform` (GatingML fasinh + CyTOF cofactor),
  `LogTransform`, `LinearTransform`, `biexponential` (FlowJo biex), `CustomTransform`,
  `estimateLogicleW`, `QuantileTransform`. Each: `scale`/`unscale` round-trip.
- **Where:** `logicleScaleInto` over a column is the #1 WASM/FFI kernel (already staged in
  `kernels/wasm.ts`; Rust started in `cytometry-wasm/src/logicle.rs`). Others follow the same seam.
  Round-trip *helpers* stay TS.

**Gating** (`src/gating/`) — membership over millions of events.
- `PolygonGate` ⚡ (ray-casting), `EllipseGate`, `RectangleGate`, `RangeGate` (1D), `quadrant`,
  boolean gates (AND/OR/NOT/difference), `evaluate1D/2D`.
- **Where:** `polygonMask` over event columns → WASM/FFI (`kernels/wasm.ts`, `cytometry-wasm/src/gate.rs`).
  Rectangle/range/boolean are per-event-cheap bitset ops → **stay TS** (`population.ts`).

**Density** (`src/density/`) — binning + contours for plots.
- `histogram2d` (source-of-truth for density plots), `histogram1d`, `kde1d`/`kde2d`,
  `hexbin`, `marchingSquares` (contour), `contour`.
- **Where:** 2D binning at interactive pan/zoom → **WebGPU** compute (atomic adds), which *must* match
  `histogram2d` bins (regression-tested headlessly). Static/one-shot binning → TS or WASM. KDE (heavy
  kernel sums) → WASM/FFI candidate.

**Compensation / unmixing** (`src/compensation/`, `src/cytof/`).
- `invertSquare` (matrix inverse), `applyCompensation`, `spilloverFromControls`/`FromMedians`,
  `unmix` (OLS/NNLS spectral), `pmtNormalize`, `validateSpillover`; CyTOF `isotopeCompensate` (NNLS),
  `debarcode`, `beadNormalize`.
- **Where:** matrices are tiny (n_channels²) → inverse stays TS. The **per-event apply/unmix loop**
  is the native target (`cytometry-wasm/src/compensate.rs` started). NNLS/WLS → vendor `faer`+`nnls`
  (Rust) if per-event.

**Clustering** (`src/cluster/`) — heavy, iterative.
- `kmeans`, `gmm` (EM diagonal), `dbscan`, `flowSOM` (SOM + metacluster), `phenograph`,
  `consensusCluster`, `agglomerative`/`hierarchical`, `labelsToPopulations`, `matchPopulations`,
  `flowCutQC`.
- **Where:** all WASM/FFI candidates. `cytometry-wasm/src/cluster.rs` started. Best vendor path:
  `linfa-clustering` (Rust: kmeans/dbscan/gmm) and `libscran/kmeans` (C++). Seed-dependent → tolerance
  oracle.

**Dimensionality reduction** (`src/reduce/`).
- `pca` (`jacobiEigen`), `mds`, `tsne`, `umap`.
- **Where:** the biggest TS pain. Vendor `libscran/umappp`, `libscran/qdtsne`, `CppIrlba` (PCA/IRLBA)
  — header-only C++ **already WASM-proven for browser single-cell analysis**. Run on reduced sets
  (≤500k), so wasm32 ceiling is a non-issue.

**Graph** (`src/graph/`) — the neighbor foundation.
- `knn` (brute-force O(N²·d) — the code itself notes "at scale this becomes HNSW/kd-tree + Rust→WASM"),
  `louvain` (community detection).
- **Where:** vendor `knncolle` (+`knncolle_annoy`/`_hnsw`) for ANN; `libleidenalg` for Leiden
  (⚠ GPL-2 via igraph). WASM/FFI.

**Stats / comparative / diff / discovery / multisample / spatial / ml / sample / autogate /
cleaning / normalize** — mostly per-event-cheap or small-N.
- `channelStats`, `percentile`/`median`, `frequency`, Mann–Whitney U, `benjaminiHochberg`,
  `foldChange`, `markerPositivity`, `coExpression`, diversity (Shannon/Simpson), differential
  abundance, `markerEnrichment`, `sampleSimilarity`, `trackPopulations`, `neighborhoodEnrichment`,
  `logisticRegression`, `concatenate`/`downsample`/`exportCsv`, Otsu/density-valley `threshold1d`,
  singlet/debris/saturation/time-window gates, `isolationForest` QC, `detectDrift`, `CytoNorm`.
- **Where:** **stay TS** by default (boundary cost dominates). Exceptions worth benching:
  `isolationForest`, `neighborhoodEnrichment`, `logisticRegression`, `CytoNorm` (heavier loops).

### 2.3 `cytometry-gpu` — rendering

Language TS + WGSL. `webgpu/{device,density,layout}.ts` + `shaders`, `canvas2d/fallback.ts`,
`colormap.ts` (viridis etc.), `density-image.ts`, `axis/ticks.ts` (logicle-aware),
`interaction/{viewport,gates}.ts` (pan/zoom about cursor, rect/polygon gate gestures).
- **Where:** **WebGPU** for the density compute+draw; **Canvas2D** fallback; the bin math mirrors
  `cytometry-core/histogram2d`. Interaction math is cheap → TS.

### 2.4 `cytometry-wasm` — the started Rust kernel crate

Language Rust (cdylib + wasm). `src/logicle.rs`, `src/gate.rs`, `src/compensate.rs`, `src/cluster.rs`,
`tests/golden.rs` (+ `logicle_golden.csv`). This is the cytometry equivalent of a bunny library — the
place the earmarked kernels land. **Recommendation:** wire it through the exact bunny pattern (native
`.dll` for `bun:ffi` server path + `.wasm` for browser worker), self-tested against the
`cytometry-core` TS goldens.

### 2.5 `engine-controller` — orchestration

Language TS. `controller.ts` operations: `loadSample`, `addSampleFromColumns`, `setAxes`,
`compensate`, `setTransform`, `density`, `addGate`, `refreshStats`, `cluster`, `embed`,
`markerEnrichment`, `exportSampleCsv`, `saveGateTemplate`/`applyGateTemplate`,
`exportWorkspace`/`importWorkspace`, `importGatingML`, plus `undo`/`redo`/`canUndo`/`canRedo`.
Also: worker RPC host (`worker/`), `backend.ts` (in-process vs worker), `store.ts`, `protocol.ts`,
`workspace.ts` (topo-sorted gate graph serialization), `interop/` (GatingML XML).
- **Where:** **always TS** — this is the conductor. It dispatches heavy ops to the worker → WASM/GPU;
  it should never itself hold a hot loop.

File formats consumed here: **GatingML 2.0** (XML gate import), workspace JSON, CSV export.

### 3.3 Which `agg` operations have a *native-acceleration* case

Almost all of `agg` is I/O, parsing, graph enumeration, and string algebra where **TS is the right
call** (correctness-critical, byte-golden-tested, not throughput-bound). The candidates that could
one day take the `granular-bunny` treatment — and which **overlap directly with bunny's un-wired MSA
cluster** — are:

| `agg` operation | File | Why native | Bunny counterpart |
|---|---|---|---|
| Pairwise alignment (SSW / Needleman–Wunsch / Gotoh) | `sanger/ssw.ts`, `pairwiseAlignment.ts`, `pairwiseAlign.ts` | O(n·m) DP, heavy on long traces | **MUSCLE/FAMSA/abPOA** (pairwise+MSA), server FFI |
| Fuzzy / full-text search (`{s<=N}`, Aho-Corasick `primer_screen`) | `search/fuzzyRegex.ts`, `overlap/` | large-index / many-pattern scans | **shellinford** (FM-index), `bioseq.fm_count` |
| Assembly graph enumeration (all simple paths / cycles) | `assembly/assembly2Engine.ts` | combinatorial blow-up on big part sets | (bespoke; keep TS unless it bites) |
| SnapGene `.dna` decode | `sgffp` (unported) | binary block parsing | (keep TS; not throughput-bound) |

> **The concrete cross-repo synergy:** stand up **one MSA/alignment/FM-index service** in

## 4. The consolidated orchestration map

### 4.1 Where each *class* of operation belongs

| Operation class | Examples | Substrate | Rationale |
|---|---|---|---|
| Orchestration / dispatch / undo / serialization | `engine-controller`, agg feature facades | **TS** | zero hot loops; conductor role |
| File parse/write, format decode | FCS, GenBank/FASTA/SnapGene, ABI/SCF/ZTR, BAM | **TS** (inner decode loop optionally native) | correctness-critical, golden-tested, not throughput-bound |
| Per-event column kernels | logicle/asinh transforms, polygon/ellipse masks, per-event compensation apply | **WASM** (browser) / **FFI** (server) ⚡ | one crossing, millions of iters, SIMD-friendly, deterministic |
| Per-event-cheap bitset/stats | rectangle/range/boolean gates, channelStats, percentiles | **TS** | boundary cost > compute |
| Interactive binning + draw | density histogram2d, scatter render, pan/zoom | **WebGPU** (Canvas2D fallback) | per-pixel/per-event at 60 fps; bins mirror TS oracle |
| Heavy iterative ML | kmeans/gmm/dbscan/flowSOM, UMAP/t-SNE/PCA, kNN/Leiden | **WASM** (reduced sets) / **FFI** (server) | O(N²)/iterative; vendor libscran/knncolle/linfa |
| Sequence alignment / MSA / full-text index | SSW/NW/Gotoh, MSA, FM-index | **TS** (browser) → **FFI** (server, vendored) | small=TS; large=native MSA service |
| Crypto / checksum / compression | BLAKE2b, CRC32, LZ4 | **WASM**/**FFI** | already vendored in bunny |
| OS-coupled (mmap/WAL/threads) | memmap scan, write-ahead log, AVX2 MSA | **FFI only** | no browser equivalent |

### 4.2 Reuse the one pattern everywhere

`granular-bunny` is not just a bio library — it is the **build+bind+self-test+bench harness** that
`001Cytometry/packages/cytometry-wasm` should adopt wholesale:

1. Vendor / author the native lib (Rust crate or C shim).
2. `build.ts`: compile to **both** `.dll/.so/.dylib` (FFI) and `.wasm`.
3. `gen-bindings.ts`: emit the typed TS FFI shim from the header/`.rs`.
4. `suite.ts` `selfTest`: every backend must equal the **TS reference** (or match within tolerance
   for seed/float-reordered algorithms) *before* timing.
5. Bench `FFI vs WASM vs TS` at real sizes (100k / 1M / 10M events; short / long / many sequences),
   and let the numbers pick the shipping backend per operation and per size.

### 4.3 First moves (highest ROI, lowest risk)

1. **Cytometry:** finish `cytometry-wasm` for the two earmarked kernels (`logicleScaleInto`,
   `polygonMask`), seeded from the existing flowutils goldens — proves the whole pipeline on real
   data shapes.
2. **Cytometry:** vendor `knncolle` + `libscran/umappp` + `qdtsne` (header-only, WASM-proven) to
   replace `reduce/` + the `graph/knn` foundation; `linfa-clustering` for `cluster/`.
3. **Bio:** wire the already-submoduled **MSA/FM-index cluster** (MUSCLE/FAMSA/abPOA/shellinford)
   into the bunny registry as one server-side alignment service, callable from `agg`'s Sanger + search.
4. **Everywhere:** keep every TS implementation as the self-test oracle — never delete the reference.
